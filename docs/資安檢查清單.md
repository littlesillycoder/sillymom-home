# 資安檢查清單

每個 issue 開 PR 前、上線前，都照這份檢查。來源：#6。有新的資安規則時，直接改這份文件。

原則：**能用現成服務就用，盡量不要自己寫，特別是資安相關的功能**（CLAUDE.md）。

---

## 一、每個 issue 都要檢查

### 資料與權限
- [ ] 新資料表都有 Row Level Security，並有「其他帳號讀不到」的測試。
  - 資料庫會自動幫 `public` 的新資料表開啟 RLS（event trigger），自動測試也會檢查。但每張表還是要在 migration 明確寫 `enable row level security` 和 policy。
  - 修改 RLS 規則時，PR 說明要特別標出來。
- [ ] 會改資料的動作一律用 POST（不用 GET）。
- [ ] 輸入的資料都有檢查（格式、長度、範圍），不信任瀏覽器送來的任何值，包括金額、使用者編號、角色。

### 金鑰與個資
- [ ] 沒有金鑰寫在程式、issue、PR、對話裡。金鑰只放 `.env.local` 和 GitHub Secrets（雲端服務的環境變數）。
- [ ] log 一律用 `@/shared/log`（`log.info`、`log.warn`、`log.error`），不直接用 `console`（lint 會擋）。
  - 地址、姓名沒辦法靠格式判斷，**只能放在有名稱的欄位**（例如 `{ address }`），不能夾在一段文字裡。
  - 事件名稱用固定的英文代號，不放變數或使用者輸入。
- [ ] 事件內容只有編號、數字、狀態，沒有個資（程式和資料庫都會擋）。

### 外部服務與套件
- [ ] 外部服務只透過替換介面呼叫（`@/shared/providers/<服務>`），不直接呼叫 API，也不 import `impl/`（lint 會擋）。
- [ ] 新增外部網域（例如綠界、LiveKit）時，更新 CSP（`src/shared/security/csp.ts`），並測試沒有被誤擋。
- [ ] 新增套件要在 PR 說明原因，並在 PR 說明特別標出來。能用現成服務或已經有的套件就不要新增。
- [ ] 套件新版本發布未滿 7 天不安裝（pnpm `minimumReleaseAge`）。真的需要時加進例外清單，並在 PR 說明原因。

### 表單與防機器人
- [ ] 註冊、登入、送驗證碼：用 Supabase Auth 內建的 Turnstile（`captchaToken`），不自己驗證。
- [ ] 其他公開表單（例如申訴）：放 `<TurnstileWidget action="…" />`，伺服器端用 `verifyTurnstile()` 驗證，action 兩邊一樣。

### 畫面
- [ ] 不用 `dangerouslySetInnerHTML`（lint 會擋）。需要粗體、連結的文字用 next-intl 的 `t.rich()`。
- [ ] 需要攝影機、麥克風的新頁面，加到 `src/shared/security/headers.ts` 的 `VIDEO_PATHS`；其他頁面一律關閉。
- [ ] 載入外部程式要帶 nonce（`next/script` 的 `nonce`，從 `headers()` 的 `x-nonce` 讀）。

### PR
- [ ] PR 開出前執行 `/security-review`，把結果摘要寫在 PR 說明。

## 二、上線前要檢查

### 安全標頭
- [ ] **CSP 從 Report-Only 改成擋下**：預覽、展示確認沒有誤擋後，正式環境一定是擋下（設成 report-only 程式會報錯）。
- [ ] 用 securityheaders.com 檢查正式網址，沒有紅色項目。
- [ ] 決定 HSTS 要不要加 `preload`（申請後很難撤回，網域和子網域都確定一直用 https 才加）。

### Cloudflare
- [ ] 限流規則（免費版 1 條）：同一個 IP 短時間內 POST 太多次就擋。合併所有敏感網址：
  - `/internal/...`（補處理、維護）
  - 之後的申訴、自己伺服器處理的表單送出網址
  - 設定內容（網址、次數、時間）記錄在這裡，並實測超過次數會被擋。
  - 注意：瀏覽器直接連 Supabase 的登入流量不經過 Cloudflare，由下面的 Supabase 限制和 Turnstile 保護。
- [ ] Turnstile 用正式金鑰，Cloudflare 後台的網站名稱只允許我們的網域。

### Supabase Auth（後台 Authentication 的設定要和 `supabase/config.toml` 一樣）
- [ ] 同一支手機 60 秒內只能送一次驗證碼（SMS max frequency = 60 秒）。
- [ ] 驗證碼 5 分鐘後失效（SMS OTP expiry = 300 秒）。
- [ ] Rate limits：同一個 IP 5 分鐘內登入和註冊 30 次、驗證 30 次；整個專案每小時簡訊數量依正式的預估流量調整。
- [ ] 開啟 Bot and Abuse Protection：Turnstile，填正式密鑰。
- [ ] 每張表都有 RLS（後台 Security Advisor 沒有警告）。

### 金鑰與服務
- [ ] 外部服務都不是 mock（正式環境設成 mock 會報錯）。
- [ ] 金鑰更換方式寫下來：每個金鑰在哪裡設定、換的時候要改哪些地方。
- [ ] 備份：Supabase 的備份已開啟，並實際試過還原一次。
- [ ] GitHub：secret scanning、push protection、Dependabot 警示都是開啟的；沒有未處理的高風險警示。

## 三、目前的設定（#6）

| 項目 | 設定 | 在哪裡 |
|---|---|---|
| 安全標頭 | HSTS 一年、X-Frame-Options DENY、nosniff、Referrer-Policy、COOP、Permissions-Policy | `src/shared/security/headers.ts` |
| CSP | 每次請求產生 nonce，所有頁面在請求時產生、不快取 | `src/shared/security/csp.ts`、`src/proxy.ts` |
| 攝影機、麥克風 | 只開放給視訊等待室、視訊室、師傅端視訊室 | `VIDEO_PATHS` |
| Turnstile | 登入類交給 Supabase；其他表單用 `verifyTurnstile()` | `src/shared/security/` |
| log 遮蔽 | 欄位名稱＋文字格式（手機、email、證件、卡號、LINE ID） | `src/shared/log/` |
| 新資料表自動開 RLS | event trigger `rls_auto_enable` | `supabase/migrations/*_security_basics.sql` |
| 套件 | Dependabot 每週檢查、新版本等 7 天；pnpm 新版本未滿 7 天不安裝 | `.github/dependabot.yml`、`pnpm-workspace.yaml` |
